# Kernel setup

The PS5 kernel is stock Linux plus one patch file and a config. Two repositories carry it:

| Repository | What it is | Get it as |
| --- | --- | --- |
| [rmuxnet/ps5-linux-patches-1](https://github.com/rmuxnet/ps5-linux-patches-1) | A fork on a newer stable kernel. Nearly everything in upstream `main` plus CPU and GPU clock drivers for the base PS5 and the Pro, its own Bluetooth patches, the IW620 Wi-Fi driver built in, and `build.sh`. | A zip with `install.sh` from its releases, or `build.sh` on the PS5. |
| [ps5-linux/ps5-linux-patches](https://github.com/ps5-linux/ps5-linux-patches) | The official patch set. Every push to `main` becomes a packaged release with the fan curve, the HDMI work, the Pro GPU and VCN. | `.deb`, `.pkg.tar.zst` and `.rpm` packages, or the [package repository](/advanced/package-repository). |

rmuxnet's repository is a fork of the official one and its work is merged upstream over time. Use it unless you need the package manager route; the two differ in the details listed under [What is where](#what-is-where). What the version strings and branches mean, and how to apply single patches on top, is on [Kernel sources and patches](/advanced/kernel-sources). [PS5 Bazzite Deck](/installation/bazzite-deck) has its own kernel and update process, see its release notes.

The loader always starts the kernel (`bzImage`) and initrd (`initrd.img`) from the FAT32 partition of the USB drive, labelled `boot` and usually mounted at `/boot/efi` (or `/efi` on Bazzite). Whatever way you install a kernel, it has to end up there.

:::warning[M.2 installs]
A kernel update on an M.2 install has left some users with a black screen or a kernel that doesn't match its modules. Read [Known issues](/troubleshooting/known-issues#kernel-update-breaks-m2-boot) before you update one.
:::

## Install rmuxnet's release

Download the release zip from the [releases page](https://github.com/rmuxnet/ps5-linux-patches-1/releases) (about 45 MB) and run its installer on the PS5:

```bash
unzip ps5-linux-<version>.zip
cd ps5-linux-<version>
sudo ./install.sh
```

Then **cold boot** the PS5 (power off, start it, run the loader). The script:

- copies the modules to `/lib/modules/<version>` and the kernel to `/boot`,
- builds the initrd with `mkinitcpio`, `update-initramfs` or `dracut`, whichever the distro has,
- writes `/etc/modprobe.d/ps5-iw620.conf` for the Marvell IW620 Wi-Fi driver that comes with the kernel, and copies its firmware from the boot partition (`lib/nxp/pcieuartiw620_combo_v1.bin`) to `/lib/firmware/nxp/` when it is there, so the internal Wi-Fi works without [ps5-linux-mwifiex](/hardware/wifi-bluetooth#wifi),
- finds the mounted partition that holds `bzImage` and asks you to confirm it (or pass the path: `sudo ./install.sh /boot/efi`),
- backs the old `bzImage` and `initrd.img` up to `/boot/efi-backup/<date>` (the last three are kept) and copies the new ones in.

To roll back, copy the backup over the files on the boot partition and cold boot again:

```bash
sudo cp /boot/efi-backup/<date>/bzImage /boot/efi/bzImage
sudo cp /boot/efi-backup/<date>/initrd.img /boot/efi/initrd.img
sync
```

The release is built with Clang, full LTO and `-march=znver2` (the PS5's Zen 2 cores); it is a kernel for the PS5, not for an ordinary PC.

:::note[PS5 Pro]
`install.sh` doesn't copy the Pro's GPU firmware into the initrd. Put the eight `viola_*.bin` files in `/lib/firmware/amdgpu/` before you run it, see [PS5 Pro](/hardware/ps5-pro#gpu-firmware). Not tested by the wiki editors with this installer.
:::

## Build with build.sh

`build.sh` builds the same kernel on the PS5 itself. It clones Linux, applies the patch, builds with Clang, installs the modules and deploys to the boot partition with the same backup as `install.sh`. A full build takes a long time on the console; the source tree stays in `../linux`, so the next one is faster.

### Dependencies

<Tabs groupId="distro">
<TabItem value="arch" label="Arch Linux">


</TabItem>
<TabItem value="debian" label="Debian / Ubuntu" default>

```bash
sudo apt install build-essential bc bison flex libssl-dev libelf-dev libncurses-dev dwarves git clang lld llvm ccache
```

</TabItem>

### Build

```bash
git clone https://github.com/rmuxnet/ps5-linux-patches-1 ps5-linux-patches
cd ps5-linux-patches
./build.sh
```

The script asks whether the partition it found with `bzImage` on it is the right one. Press <kbd>Enter</kbd> to use it, or `n` to type the path. Cold boot when it is done. Roll back as above; the script prints the backup folder.

All options are in `build.cfg`. Copy it to your own file and pass that to `build.sh` to change them:

| Option | Default | What it does |
| --- | --- | --- |
| `KERNEL_REF` | The tag the patch set targets | The kernel tag to build. Point releases come from the stable tree, release tags from mainline. |
| `LTO` | `full` | `full`, `thin` or `none`. Full LTO needs the most memory. |
| `MARCH`, `MTUNE` | `znver2` | CPU flags. Keep them for the PS5. |
| `CCACHE` | `y` | Caches object files in `~/.cache/ccache` so rebuilds are faster. |
| `SWAP_GB` | `auto` | Adds a swap file for the build: 10 GB with full LTO, 6 GB with thin, none without. |
| `EFI_DIR` | `auto` | The boot partition. Set it to skip the question. |
| `DEPLOY_EFI` | `y` | `n` builds and installs the modules without touching the boot partition. |

The Wi-Fi driver for the Marvell IW620 (NXP `mwifiex`, already patched for the kernel version) is in `oot/mwifiex` and is built with the kernel. Nothing else is needed for Wi-Fi.

### Build by hand

Without the script, the steps are the usual ones. The `.config` is made with Clang, so always pass `LLVM=1`, and keep the folder name `ps5-linux-patches`: the config loads the [VCN firmware](/hardware/gpu#video-engine) from `../ps5-linux-patches/firmware`. Use the kernel tag named in the first lines of `.config`.

```bash
git clone https://github.com/rmuxnet/ps5-linux-patches-1 ps5-linux-patches
git clone --depth 1 --branch <kernel-tag> https://git.kernel.org/pub/scm/linux/kernel/git/stable/linux.git
cd linux
git apply ../ps5-linux-patches/linux.patch
cp ../ps5-linux-patches/.config .config
make LLVM=1 olddefconfig
make LLVM=1 -j$(nproc)
sudo make LLVM=1 INSTALL_MOD_STRIP=1 modules_install
```

For Wi-Fi, copy the driver into the tree before you build:

```bash
cp -a ../ps5-linux-patches/oot/mwifiex drivers/net/wireless/nxp-wlan
sed -i 's/\$(CONFIG_NXP_WLAN_DRIVER)/m/g' drivers/net/wireless/nxp-wlan/Makefile
echo 'obj-m += nxp-wlan/' >> drivers/net/wireless/Makefile
```

The same steps work for upstream `ps5-linux-patches` (clone that repository instead; its `.config` is for GCC, so `LLVM=1` is optional there, and it has no `oot/` driver).

:::tip[Keep the initrd small]
`INSTALL_MOD_STRIP=1` installs the modules without debug symbols. Without it an `amdgpu.ko` is hundreds of megabytes, the initrd grows accordingly and boot is slow.
:::

### Copy the kernel to the boot partition

`make install` doesn't put anything where the loader looks. Build the initrd for the new kernel, back up the current files on the boot partition and copy the new ones in. Run this from the `linux` folder:

<Tabs groupId="distro">
<TabItem value="debian" label="Debian / Ubuntu" default>

```bash
KVER=$(make -s kernelrelease LLVM=1)
sudo update-initramfs -c -k "$KVER"
sudo cp /boot/initrd.img-$KVER /tmp/initrd.img
```

</TabItem>
<TabItem value="arch" label="Arch Linux">

```bash
KVER=$(make -s kernelrelease LLVM=1)
sudo mkinitcpio -k "$KVER" -g /tmp/initrd.img
```

</TabItem>
</Tabs>

```bash
sudo mv /boot/efi/bzImage /boot/efi/bzImage.old
sudo mv /boot/efi/initrd.img /boot/efi/initrd.img.old
sudo cp arch/x86/boot/bzImage /boot/efi/bzImage
sudo cp /tmp/initrd.img /boot/efi/initrd.img
sync
```

If the new kernel doesn't boot, rename the `.old` files back from another computer (the boot partition is FAT32, so any PC can open it).

## Install upstream's packaged kernel

The official repository publishes `.deb`, `.pkg.tar.zst` and `.rpm` packages on its [releases page](https://github.com/ps5-linux/ps5-linux-patches/releases) for every commit on `main`. The easiest way to get them is the [package repository](/advanced/package-repository): it installs the kernel with your package manager, copies it to the boot partition for you and keeps it up to date. Or install a downloaded package by hand:

<Tabs groupId="distro">
<TabItem value="debian" label="Debian / Ubuntu" default>

```bash
sudo dpkg -i linux-ps5_*.deb
```

</TabItem>
<TabItem value="arch" label="Arch Linux">

```bash
sudo pacman -U linux-ps5-*.pkg.tar.zst
```

</TabItem>
</Tabs>

A current package brings the fan curve and the GPU governor; the CPU boost still needs `ps5_control` from [ps5-linux-tools](/hardware/gpu#clocks-and-boost), the IW620 Wi-Fi needs [ps5-linux-mwifiex](/hardware/wifi-bluetooth#wifi) (the package repository bundles it), and the Slim's and Pro's Bluetooth fixes aren't upstream.

## Build a kernel for Bazzite Game Mode

Bazzite's Game Mode starts Steam through the `cardwired` service, which loads an eBPF program. That needs two kernel features:

1. **The BPF LSM.** `CONFIG_BPF_LSM=y` is set in both configs, but `bpf` is missing from `CONFIG_LSM`, so it never activates. Add `bpf` to `CONFIG_LSM`, or add `lsm=landlock,lockdown,yama,integrity,apparmor,bpf` to `cmdline.txt`.
2. **Kernel BTF.** `CONFIG_DEBUG_INFO_BTF=y` is in both current configs. Check that `/sys/kernel/btf/vmlinux` exists; older configs need it turned on.

Without them, `cardwired` crash-loops with `CardwireEbpfError(LSMNotEnabled)` or `error parsing /sys/kernel/btf/vmlinux`, Gamescope is killed a second after it starts, and after five attempts Bazzite drops you to the desktop. [PS5 Bazzite Deck](/installation/bazzite-deck) applies both changes.

## Kernel parameters (cmdline.txt)

The kernel command line is stored in `cmdline.txt` on the FAT32 partition of your USB drive. Edit it to pass your own parameters. From Windows, see [Edit cmdline.txt from Windows](/installation/linux-image#edit-cmdlinetxt-from-windows).

The default command line looks like this (it varies slightly between images):

```text title="cmdline.txt"
root=LABEL=__DISTRO__ rw rootwait console=ttyTitania0 console=tty0 mitigations=off idle=halt preempt=full
```

- `console=ttyTitania0`: the console's UART, under Sony's name for it. Only matters when you debug over a serial cable.
- `mitigations=off`: the CPU vulnerability mitigations are off for speed. Set `mitigations=auto` to turn them back on.
- `idle=halt`: try removing it if you notice micro-stuttering, see [GPU performance tips](/hardware/gpu#performance-tips).

Common display-related parameters:

```text
# Force 1080p if the display isn't detected correctly
amdgpu.force_1080p=1

# Remove this if you get a black screen
video=DP-1:1920x1080@60
```

Other useful parameters. Not every kernel has every HDMI parameter; the split is on [HDMI chip](/hardware/hdmi#kernel-parameters):

| Parameter | What it does | More info |
| --- | --- | --- |
| `amdgpu.ps5_cu_unlock=3` | Unlocks all disabled GPU compute units | [40 CU unlock](/hardware/gpu#40-cu-unlock) |
| `ttm.pages_limit=...` | Raises the GPU memory (GTT) ceiling | [VRAM](/hardware/gpu#vram) |
| `video=HDMI-A-1:3840x2160@60` | Forces a 4K mode | [4K black screen](/hardware/hdmi#4k-display-black-screen-after-login) |
| `drm.edid_firmware=...` | Loads a custom EDID file | [Custom EDID](/hardware/hdmi#custom-edid-injection) |
| `usb-storage.quirks=xxxx:yyyy:u` | Turns off UAS for one USB drive | [USB drive](/hardware/storage#usb-drive-required) |
| `rootwait rootdelay=60` | Waits up to 60 seconds for a slow USB drive before giving up on the root filesystem | [USB drive](/hardware/storage#usb-drive-required) |
| `usbcore.autosuspend=-1` | Stops USB devices from going to sleep, which can drop the drive | [USB drive](/hardware/storage#usb-drive-required) |
| `usbc_dp.enable=1` | DisplayPort output on the front USB-C port | [HDMI chip](/hardware/hdmi#kernel-parameters) |
| `hdmi.frl_4k120=0` | Never offers 4K at 120 Hz (upstream and rmuxnet: turns native FRL off altogether) | [HDMI chip](/hardware/hdmi#kernel-parameters) |
| `hdmi.hdcp_mode=<n>` | HDCP on the HDMI output (upstream and rmuxnet) | [HDMI chip](/hardware/hdmi#kernel-parameters) |
| `hdmi.allm=<0,1,2>` | Auto low latency mode on FLAVA3 (upstream and rmuxnet) | [HDMI chip](/hardware/hdmi#kernel-parameters) |
| `hdmi.vrr=0` | Never offers VRR (PS5 Bazzite Deck) | [HDMI chip](/hardware/hdmi#vrr-on-flava3) |
| `hdmi.rgb_range=<0,1,2>` | AVI RGB range flag: full, limited or none (PS5 Bazzite Deck) | [HDMI chip](/hardware/hdmi#rgb-range) |
| `amdgpu.ps5_viola_fw=0` | PS5 Pro: always use the base PS5's GPU firmware | [PS5 Pro](/hardware/ps5-pro#gpu-driver) |
| `ps5_gpufreq.temp_limit=<50-95>` | Thermal limit of the GPU clock governor (upstream and PS5 Bazzite Deck), 85 °C by default | [PS5 Pro](/hardware/ps5-pro#gpu-driver) |
| `btusb.ps5_tx_ep=<n>` | ACL bulk OUT endpoint for the MediaTek Bluetooth on the Slim (rmuxnet and PS5 Bazzite Deck) | [Bluetooth](/hardware/wifi-bluetooth#mediatek-on-the-slim) |
| `btusb.ps5_ep_resync=1` | PS5 Pro: resync the Bluetooth endpoints after the firmware setup (rmuxnet) | [Bluetooth](/hardware/wifi-bluetooth#mediatek-on-the-pro) |

`cmdline.txt` must stay a **single line**. Add options at the end, separated by a space.

## VRAM (vram.txt)

The default VRAM allocation is 512 MB and dynamic. To change it, edit `vram.txt` on the FAT32 partition. The value is a **hexadecimal byte count**, not decimal megabytes. See [VRAM](/hardware/gpu#vram) for the correct format and a table of sizes.
